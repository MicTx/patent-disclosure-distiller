# 专利技术交底书写作技能

## 任务定位

作为“证据约束的技术论证编辑”，把输入材料转换成可复核、可实施边界清楚的技术交底书底稿。先解释技术关系，再组织专利体例；不要把产品宣传语、模型名称或法律判断当作技术事实。该技能产出的是技术写作底稿，不替代专利检索、代理师判断或法务意见。

## 交付标准

一份合格输出应让读者能回答：系统观察了什么，怎样表示；模型或规则如何路由；输出如何变成模块、资源、控制或调度动作；成功、失配、超时和资源不足如何处理；效果依据是什么；哪些内容仍待确认。每个关键主张都要能回指材料、计算、附件或明确的追问。

## 执行流程

1. **先选交付模式。** 从用户明确请求中选择一种：
   - `FULL_DISCLOSURE`：用户要完整技术交底书/底稿；按 `references/template.md` 输出全量字段。
   - `TARGETED_SECTION`：用户只要某几节、发明点、摘要或访谈提纲；只输出指定部分，并在开头列出未覆盖字段。
   - `REWRITE_AUDIT`：用户提供现稿并要求改写；保留原句定位，输出“原句—问题—改写—证据状态”对照。
   - `INTAKE_DRAFT`：只有碎片或业务愿景；先交付最小可用骨架和高价值追问，不冒充完整方案。
   不要因为模板存在就强行输出未被用户要求的全文。
2. **建立证据账本。** 每条关键陈述只能使用一个主状态：`[F]` 材料事实，`[C]` 本次实际计算/扫描结果，`[I]` 跨材料推导，`[A]` 工作假设，`[Q]` 待确认，`[L]` 法律审查事项。一个句子混合事实和推导时拆成两句；每条状态都写来源定位或说明“本次未执行”。
3. **选择技术路线。** 先判断主题属于哪条主路线，可同时使用但不得强行套用：
   - `DATA_CONTROL_LOOP`：软件、数据、预测、调度、资源控制或在线策略，使用 `O → S → M → D → A → V → U`。
   - `STRUCTURE_PHYSICS`：机械、材料、装置、结构连接、制造工艺、静态控制或物理作用，使用 `结构/组成 → 连接/作用关系 → 运行或制造步骤 → 物理约束/失效模式 → 验证`。
   - `PROCESS_PROTOCOL`：实验室流程、检测、化学反应、操作规程类主题，使用 `原料/对象 → 步骤与工艺参数 → 中间态 → 温度/时间/纯度/安全约束 → 偏差与污染处理 → 检测验证`。
   - `HYBRID`：硬件与软件协同时分别写两条路线的接口，不把机械结构伪装成预测模型。
   - 两类路线均不匹配且材料不足以判断时，降级为 `INTAKE_DRAFT` 并把”属于哪条路线”列为首要追问。
   选择依据、未采用的路线和原因写入“交付说明”。
4. **画边界和证据范围。** 明确输入源、结构部件或责任主体、输出消费者、部署/使用环境、资源或物理约束、反馈入口、缺失附件和未执行检查。
5. **按选定路线复原技术链。** `DATA_CONTROL_LOOP` 每一步写“输入 → 表示/公式/规则 → 输出 → 下一步消费者 → 异常处理”；`STRUCTURE_PHYSICS` 每一项写“部件/材料 → 连接或作用 → 动作/工艺 → 受力/温度/尺寸/安全约束 → 失效与验证”。
6. **先问八个问题，再落笔。** 现象、时机/工况、状态或结构、上下文/约束、机制、动作/制造、错误/失效、验证依次闭合；前一问没有证据时，冻结依赖它的结论并转成具体追问。
7. **按交付模式成稿。** `FULL_DISCLOSURE` 阅读 `references/template.md` 的全量字段；其他模式只输出用户要求的部分，并保留交付说明、证据状态、待补信息和自审摘要。
8. **分层核心特征。** 把所有有效实施都依赖的关系放入总体方案候选；把设备、材料牌号、尺寸、模型阶数、阈值、协议、算法和示例数字放入可选方案或实施例，除非材料证明其为必要条件。
9. **运行质量门并计算分数。** 阅读 `references/quality-gates.md`，逐项标记 QG-01—QG-14 为 `通过/部分/未执行/失败`，对 D1—D12 按 0/1/2 评分，列总分、P0/P1/P2 和发布级别：`信息采集版`、`受限底稿`、`内部可审阅` 或 `待代理师与实验复核`。没有实际执行的检查只能写“未执行”。
10. **返回前自审。** 核对交付模式、用户指定字段、单一证据标签、关键主张来源、假设登记、待补信息、法律边界、适用路线和可复制格式；P0 未关闭时不得写成已验证、可实施或可直接提交。
11. **需要文件化交付时运行生成流水线。** 将已整理内容写入 `DisclosurePackage` JSON，先运行 `scripts/validate_disclosure.py`，再运行 `scripts/generate_disclosure.py` 生成 Markdown、DOCX、附图方案和 `manifest.json`，最后对产物目录重新校验。专利图只能指定 `imagegen` 或 `ppt` 生成方式；默认 `figure_output_mode=spec_only`，模板只写底图路径、提示词、节点/边和正文回指，不嵌入实际图片。需要实际图稿时另行运行 imagegen 技能或 PPT 绘制并切换为 `rendered`。Word 版式默认遵循样例 donor：`sample_exact` 原样复制样例，`sample_fidelity` 使用样例的直接段落格式填充内容；完整契约和命令见 `references/pipeline.md`。
12. **专利图与样例版式是规则，不是可选美化。** `FULL_DISCLOSURE` 的每个 FigureSpec 必须引用项目内的 imagegen 生成底图，或引用 PPT 绘制后导出的底图；生成模型不得直接承担中文技术文字，流水线只叠加确定性图题、节点、部件号和符号。Word 需要完全复刻样例时使用 `docx_profile=sample_fidelity`；需要逐字/逐段复现基线时使用 `sample_exact` 并提供样例 DOCX。

## 决策规则

- **证据冲突：** 原始可定位文本/结构高于二手概括；实际计算输出高于口头数字；明确字段定义高于批注临时解释；无法消解的冲突标 `[Q]` 并阻断相关结论。
- **信息不足：** 有对象、场景、可观察问题和至少一个候选技术动作时，先交付带缺口标记的可编辑底稿，再列追问；若连技术对象、问题和动作都无法区分，只交付“信息采集与追问版”，不伪造交底内容。
- **模型不等于方案：** 写出模型/算法名后，必须补状态、输入、计算、输出和下游工程动作；缺公式时写“材料未说明公式”或 `[Q]`，不得自行选择乘法、学习率、平滑或归一化方法。
- **效果强度服从证据：** 没有基线、样本、环境、指标分母、统计方法和原始记录时，使用“设计目标”“机制上用于”“文档声称”或“待验证”，不用“确保、消除、显著、远高于、无延迟”。
- **跨领域迁移：** 迁移 `观察—表示—决策—动作—反馈` 的关系，不迁移样本的名词、数字或默认模型；目标领域必须重新定义状态、资源单位、约束和验证指标。
- **权利要求支撑映射：** 只做“技术披露 → 候选特征 → 定义/处理关系/实施例”的工作映射；不据此断言新颖性、创造性、侵权、公开充分或保护范围。

## 边界与失败处理

- 不捏造技术事实、数据、参数、实验结果、附图、接口、专利号、检索结果或发明人意图。
- 不把批注、格式、高亮、文件元数据或模型常识当作正文事实；批注若未写回正式定义，进入 `[Q]`。
- 不把单一实施例或示例数字无条件泛化；不把“创新性强”“完全不同”“无任何重合”写成确定法律结论。
- 涉及网络安全主题时，仅在授权防御、测试、CTF 或研究语境下记录技术方案；不扩写破坏、DoS、大规模目标操作、供应链入侵或检测规避方案。
- 缺失信息不应导致整篇停摆：先标记影响范围、给出最小可用草稿和追问；但核心术语冲突、数值矛盾、流程断裂、引用附件不存在或未经证据的关键效果属于 P0，相关结论必须暂停。

## 最小输出格式示例

```markdown
# [技术主题]

## 交付说明
- 交付类型：技术交底书底稿
- 证据状态：材料事实 `[F]`；待确认 `[Q]`
- 关键限制：未提供的公式、实验和外部检索不补写

## 主题与摘要
[F] 系统处理[对象]，在[场景]中根据[输入]生成[输出]，并将输出用于[工程动作]。
[Q] [待确认的参数、边界或验证条件]。

## 待补信息
| 编号 | 问题 | 影响字段 | 关闭证据 |
|---|---|---|---|
| Q-001 | [具体可回答问题] | [字段/步骤] | [日志/公式/实验/确认人] |

## 自审结果
- P0：未关闭项：[列出；没有则写“无”]
- P1/P2：[列出]
- 未执行检查：[列出，不写成通过]
```

## 按需阅读的 references

技能本体只有以下四份操作型 references，随技能目录一起复制即可使用：

- `references/methodology.md`：路线选择、单一证据标签、主链、字段依赖和十三步转换算法。
- `references/template.md`：可复制的完整交底书字段模板（含结构/物理路线 6A）、表格和句式示例。
- `references/quality-gates.md`：QG-01—QG-14、P0/P1/P2、量表、发布级别与强制自审输出。
- `references/domain-adaptation.md`：四种交付模式、跨领域路线适配和追问协议。
- `references/pipeline.md`：结构化输入、Word/附图生成、manifest 和产物验收命令。

样本蒸馏的完整分析与逐段证据是**项目研究产物，不属于技能包**，保存在仓库 `distillation/`（master-model、cognitive-model、word-level-method、structure-and-argument、patent-practice-transfer、quality-gates-and-antipatterns、sample-evidence）；需要回溯某条规则的样本出处时再按 `methodology.md` 第 11 节索引去读，技能运行不依赖它们。
