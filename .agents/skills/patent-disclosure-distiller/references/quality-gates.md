# 质量门、失败处理与自审协议

## 1. 使用方式

本文件把交底书质量定义为可执行检查，而不是篇幅或专利腔。每个质量门都记录：检查问题、通过条件、失败处理、证据状态。检查未实际执行时标“未执行”；检查失败时保留问题定位并降低交付级别。

质量等级：

- **P0 阻断发布：** 核心术语无法区分；数字/正文矛盾；输入输出断裂；引用图、表、公式或数据不存在；未经证据的关键效果写成已验证；技术叙事越过法律结论边界。
- **P1 限制发布：** 边界条件、并发/生命周期约束（数据路线：缓存并发、更新优先级；结构路线：公差累积、磨损疲劳等长周期项）、实验协议或实施例复现材料不完整；可供内部讨论，但结论必须标“待确认/待验证”。
- **P2 编辑修复：** 标题、编号、术语表、表格、句子节奏、空段或残留编辑标记问题；修复若改变技术语义，升级为 P0/P1。

## 2. QG-01—QG-14

### QG-01 交付范围与完整性

- **检查：** 文中引用的附图、表格、公式、附件、数据集、代码和外部文献是否存在且可唯一定位？交付是否声明包含/不包含摘要、权利要求、附图和实验材料？
- **通过：** 建立“引用项—文件/部件—定位—状态”清单。
- **失败：** 删除不存在的承诺，或列入待补；目标为完整申请文件时阻断该标签。

### QG-02 结构与层级

- **检查：** 章节、步骤、列表、实施例和参数继承是否可解析？主方案与实施例的默认/覆盖关系是否清楚？
- **通过：** 稳定标题层级、字段编号和参数作用域；编辑元数据不承担技术语义。
- **失败：** 重排为结构化标题/表格，补继承表；格式修复触及技术语义时重新审查。

### QG-03 定义完整

- **检查：** 对象、事件、状态、目的、预测、资源、指标、模块、版本和边界是否都有可操作定义、单位或例子？
- **通过：** 独立读者可据定义判断字段取值和变化。
- **失败：** 建术语表；将“高频、智能、精准、范围、适配”等词改为可测条件，未定义者转 `[Q]`。

### QG-04 术语一致性

- **检查：** 当前事件、历史事件、用户目的/标签、预测事件、场景和验证标签是否分开？同词在全文是否只有一个含义？
- **通过：** 给定一条事件可分别写出各字段、生成时点和消费步骤。
- **失败：** P0 冻结依赖字段的模型和效果；重写字段关系并要求样例或来源。

### QG-05 数值、符号和引用一致

- **检查：** 矩阵/向量行和、最大值、并列值、阈值、单位、编号、变量和文件名是否一致？
- **通过：** 自动检查和人工回指均通过；四舍五入有容差和未舍入值说明。
- **失败：** P0 暂停数值结论；先修数据/正文，重新运行检查；不能以“约”“大概”掩盖矛盾。

### QG-06 输入—处理—输出闭合

- **检查：** 每个步骤的输入来自哪里，经过什么规则/公式，产出什么，由谁消费？是否有类型、单位、版本、缺失处理？
- **通过：** 最小事件流可逐步重算。
- **失败：** 补数据契约、伪代码或流程图；缺空间/接口/资源规则时暂停“可实施”措辞。

### QG-07 算法可实施与公式

- **检查：** 权重、阈值、归一化、平滑、零频率、更新、版本和参数来源是否足够？独立实现者能否得到同一关键结果？（结构路线：连接关系、配合公差、材料选择依据、工艺参数窗口是否足够复现装配/制造？）
- **通过：** 有公式、伪代码、样例输入输出和边界路径。（结构路线：有连接示意/尺寸链描述、关键公差和工艺条件。）
- **失败：** 数字降为示例参数；列出需补公式、原始频率、学习率、归一化或更新协议的 `[Q]`。（结构路线：列出需补牌号、公差、工艺窗口的 `[Q]`。）

### QG-08 流程连续性与任务生命周期

- **检查：** 首次、连续、命中、失配、超时、取消、重试、回滚和版本切换是否均有路径？异步任务是否有唯一 ID、取消语义和响应版本校验？（结构路线：装配/运行步骤是否连续、每步有承接部件？失效后是否有停止、止逆、提示或维修路径？）
- **通过：** 正常和异常路径均有终止条件、资源回收和记录字段。（结构路线：正常与失效路径均有终态与可检查表现。）
- **失败：** 补状态机、取消/回滚协议、超时重试和旧响应防覆盖规则。（结构路线：补失效模式表、止逆/防护特征和检查方式。）“重新执行步骤 X”不算完整异常处理。

### QG-09 边界与资源约束

- **检查：** 是否处理低样本、未知、并列、低置信度、越界、离线/弱网、容量不足、权限失败、快速重复输入和模型漂移？（结构路线：超程/超载/超温、装配干涉、公差累积、误操作、磨损疲劳和环境影响。）
- **通过：** 每个边界有判定、降级动作、资源上限和日志。（结构路线：每个边界有判定与防护/止逆特征及检查方式。）
- **失败：** 设为 P1；效果改为条件性；补决策表和测试样例。（结构路线：补 6A.3 行与试验/检查项。）

### QG-10 效果可验证

- **检查：** 每个准确率、延迟、错误率、请求量、资源量或收益是否有指标分母、基线、环境、样本、时间窗、统计方法和原始数据？
- **通过：** 独立复核者可重算，且效果能回指技术动作。
- **失败：** 改为“设计目标/机制预期/文档声称/待验证”；删除绝对化保证句。

### QG-11 实施例可复演

- **检查：** 至少一条链路是否有最小输入、参数、环境、每个中间量、输出、异常轨迹和预期结果？
- **通过：** 脱敏或合成包可逐步复演，版本和哈希可追踪。
- **失败：** 补复现包；没有材料时标“示意实施例”，不写“经过测试”。

### QG-12 主方案/实施例参数优先级

- **检查：** 默认值、覆盖条件、适用场景、版本、统计窗口和样本集关系是否明确？
- **通过：** 主方案删除实施例后仍自洽，实施例只覆盖或新增明确内容。
- **失败：** 统一规则或显式声明覆盖优先级；不能自行择一解释冲突数字。

### QG-13 泛化/限定平衡

- **检查：** 是否从一个实施例泛化到所有场景，或把示例设备/协议/数字写成必要条件？
- **通过：** 核心、可选、示例、实验观察和未验证范围分层。
- **失败：** 降低泛化强度；补替代实施或必要性证据；只保留技术关系，不复制样本参数。

### QG-14 反幻觉和证据分级

- **检查：** 每条关键句能否回指原文、附件、实际命令输出或明确的推导？是否把批注、格式、模型常识、作者声称或专利比较写成事实？
- **通过：** 关键主张有 `evidence_type`/状态标签和定位；未执行项显式列出。
- **失败：** 删除无来源句，改为 `[A]/[Q]` 或具体追问；外部专利和性能结论与技术事实隔离。

## 3. 常见反模式与修复

| 反模式 | 识别信号 | 修复 |
|---|---|---|
| 只有模型名 | “采用 AI/区块链/马尔可夫链进行优化”但无输入输出 | 写状态、计算、输出、动作和异常 |
| 只有效果 | “显著提高效率/降低延迟”无机制和基线 | 回到动作→系统量→指标→条件 |
| “结合/动态/智能”遮蔽步骤 | 关系词后没有操作和中间产物 | 拆成输入、处理、输出三句 |
| 批注替代定义 | 正文无法执行，关掉批注即缺关键规则 | 写回正式字段/公式；未解决批注转 `[Q]` |
| 示例变通用 | 单设备/单网络/单数字被写成所有场景 | 标为实施例参数并给边界/替代 |
| 现有技术绝对比较 | “完全不同、无重合、领先所有技术” | 限定比较维度，外部检索和法律审查另列 |
| 长句堆动作 | 采集、计算、判断、执行、效果挤在一句 | 拆成输入—处理—输出微结构 |
| 伪造验证 | 未运行测试却写“已验证/经实验” | 写“未执行”，列所需实验包 |
| 格式承载技术语义 | 高亮、颜色、缩进、手工编号被当作创新点 | 用定义、字段表、步骤和来源表达 |

## 4. 自审量表与强制输出

每项按 `0/1/2`：`2` 有原文、计算、实验或附件复核；`1` 有部分支撑且明确 `[A]/[Q]`；`0` 缺失、矛盾、无法复演或无证据强断言。

| 维度 | 问题 | 关联质量门 |
|---|---|---|
| D1 交付范围 | 读者知道稿件类型和缺失部件吗？ | QG-01 |
| D2 问题因果 | 现象、缺口、后果和目标连得上吗？ | QG-03 |
| D3 术语字段 | 事件、目的、预测、资源、反馈分层了吗？ | QG-03/04 |
| D4 I/O | 每步输出有消费者吗？（结构路线：每个作用有承接部件） | QG-06 |
| D5 模型公式 | 参数、归一化、更新可复核吗？（结构路线：连接、约束、尺寸链可复核） | QG-07 |
| D6 决策动作 | 模型结果改变了实际动作吗？（结构路线：结构特征改变了受力/运动） | QG-06 |
| D7 错误代价 | 失配、超时、取消、回滚闭合吗？（结构路线：失效模式与防护闭合） | QG-08/09 |
| D8 数值一致 | 数字、单位、变量、版本一致吗？ | QG-05/12 |
| D9 实施复演 | 至少一条路径可重算吗？ | QG-11 |
| D10 效果证据 | 指标、基线、条件、原始数据齐吗？ | QG-10 |
| D11 法律边界 | 技术差异和法律判断分开吗？ | QG-13/14 |
| D12 语言可审计 | 句子有主语/输入/动作/输出和条件吗？每句单一证据标签？ | QG-14 |

建议门槛：关键项 D1、D3、D4、D5、D8、D10、D11 不得为 0；总分达到 20/24 才标“内部可审阅”；达到 23/24 且 P0/P1 关闭，才可进入代理师/实验复核。该分数是编辑门槛，不是法律标准。

**强制输出规则：** 无论交付模式（`FULL_DISCLOSURE`、`TARGETED_SECTION`、`REWRITE_AUDIT`、`INTAKE_DRAFT`），最终回复必须包含“自审结果”块，其中至少有：D1—D12 逐项 0/1/2 分与总分、P0/P1/P2 未关闭项清单、明确的一个发布级别（`信息采集版`/`受限底稿`/`内部可审阅`/`待代理师与实验复核`）和“未执行检查”列表。`TARGETED_SECTION` 等局部交付只对已输出部分评分，并在自审中注明未覆盖维度记 `未评估`，不得记 0 或 2。

## 5. 发布前检查记录格式

```markdown
### 质量门检查记录
- 检查时间/版本：[时间、版本]
- 已实际执行：[命令、脚本、人工回指范围及完整输出摘要]
- P0：[无/列问题、定位和阻断动作]
- P1：[无/列问题和降级写法]
- P2：[无/列编辑修复]
- 未执行：[渲染/外部检索/性能实验/原始日志/安全评估]
- 发布级别：[信息采集版/受限底稿/内部可审阅/待代理师与实验复核]
```

## 6. 失败处理优先级

- 若缺少对象、现象、候选动作：返回信息采集版，先问系统边界和技术问题。
- 若术语冲突影响模型：保留双方原文，建立字段对照，阻断依赖结论。
- 若数字和正文矛盾：保留计算输出和原文定位，标 P0，不猜“四舍五入”。
- 若效果无基线/原始数据：保留“文档声称”作为来源事实，但不写实测结论。
- 若引用材料不存在：删除承诺或标缺失；不生成“已有附图/实验”。
- 若仅有产品愿景：把技术机制列为 `[A]` 候选并要求发明人确认；不把愿景包装为已实现方案。
