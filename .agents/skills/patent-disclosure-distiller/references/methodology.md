# 方法论：证据约束的可迁移技术论证

## 0. 路线选择与单一标签规则

### 0.1 技术路线

起草前先选主路线，写入交付说明；不得把一条路线强套到另一类主题上：

- **`DATA_CONTROL_LOOP`（数据/控制闭环）**：存在数据采集、规则或模型、决策、资源/控制动作与反馈更新的主题。主链 `O → S → M → D → A → V → U`（见第 3 节）。
- **`STRUCTURE_PHYSICS`（结构/物理）**：机械、材料、装置、连接结构、制造工艺、静态控制或物理作用主题。主链为 `对象/部件/材料 → 连接/位置/界面关系 → 运行或制造步骤 → 受力/温度/尺寸/流体/电气/安全约束 → 失效模式/防护 → 验证`。不强行补预测模型、在线更新或缓存生命周期；最小字段契约是“部件或材料 + 几何/成分/状态 + 连接或作用关系 + 运行/制造动作 + 物理约束/边界 + 输出状态/功能 + 失效模式/防护 + 验证证据 + 来源定位”。
- **`PROCESS_PROTOCOL`（工艺/流程）**：实验室流程、检测、化学反应、操作规程类主题（既非预测控制系统也非静态结构）。主链为 `原料/对象 → 步骤与工艺参数 → 中间态 → 温度/时间/纯度/安全约束 → 偏差与污染处理 → 检测验证`；异常类别用“偏差/污染/超时/中断”表述，不套用计算层词汇。
- **`HYBRID`（混合）**：硬件结构与软件控制协同时分别闭合两条路线，再写接口字段、时序、权限、失效与验证关系；不得用模型名替代结构关系。
- **无匹配分支**：所有路线均不匹配且材料不足以判断时，降级为 `INTAKE_DRAFT`，把“属于哪条路线”列为首要追问，不得强行套用任何主链。

路线判断写成：`[I] 本稿采用 STRUCTURE_PHYSICS，因为输入材料描述部件作用与物理约束；未采用在线预测路线。`

### 0.2 单一证据标签

每个可独立判断的句子只带一个主标签；禁止 `[F/I]`、`[F/Q]` 等混合标签。需要表达不同状态时拆成相邻句：

```text
[F][材料定位] 材料明确写出[事实关系]。
[I] 基于上述事实，本文将[推导]作为候选表达。
[Q] 仍需补充[字段/公式/边界/实验]，否则不能确认[结论]。
```

- 表格单元格同时含事实与推导时，拆行或加“证据状态”列；每行仍只取一个主状态。
- `[C]` 必须附实际执行的命令与输出摘要；未执行就写 `[Q]` 并列入“未执行检查”。
- `[A]` 必须写影响与关闭证据；假设不得写成已实施事实或法律结论。

## 1. 适用范围与总原则

本文件把 `distillation/master-model.md` 及其引用的六份蒸馏材料压缩为可执行方法。它服务于技术交底书底稿、发明点梳理、现有稿件改写和跨领域技术主题转换。它不把样本中的 GIS 名词、马尔可夫阶数、概率数字或效果百分比当作通用事实。

核心主张是：迁移“观察—表示—决策—动作—反馈”的关系，而不是迁移样本的领域外壳。完整技术叙事应能回答：系统何时观察什么；怎样形成状态或数据表示；在什么信息条件下选择哪条计算路径；输出如何改变资源、控制、调度、权限或时序；成功、失配和资源不足如何处理；反馈怎样更新下一轮。

材料依据：`distillation/master-model.md` 第 1、2、6、8、9、10、11 节；`distillation/structure-and-argument.md` 第 1、2、4、5、9、10 节；`distillation/cognitive-model.md` 第 1、2、4、5、9、10 节。

## 2. 证据账本

### 2.1 六类状态

| 标记 | 含义 | 可写内容 | 写法限制 |
|---|---|---|---|
| `[F]` | 原始材料明确事实 | 对象、步骤、字段、参数、实施例 | 附文件/段落/页码/附件定位；不扩展语义 |
| `[C]` | 本次实际计算或结构扫描 | 行和、最大值、文件构成、字符串匹配 | 保留命令、输入和完整输出；未运行不写 `[C]` |
| `[I]` | 从事实关系推导的通用方法 | 结构规则、编辑建议、技术关系解释 | 明确是推导，不能回写成材料已实现功能 |
| `[A]` | 工作假设 | 为继续起草而暂时采用的条件 | 写出假设、影响、责任人/确认项和有效范围 |
| `[Q]` | 待确认 | 缺少公式、字段、边界、附件或冲突解释 | 转换成具体问题；相关结论保持降级 |
| `[L]` | 法律审查事项 | 需要检索、法域、代理师或法务判断的内容 | 只记录审查入口，不给确定的新颖性/创造性/侵权结论 |

### 2.2 证据强度与句子强度

- 事实句：`[F] 材料在[定位]写明……`。
- 计算句：`[C] 执行[命令]得到[输出]`。
- 推导句：`[I] 基于[事实]，建议将……`。
- 假设句：`[A] 暂按……起草；若确认不同，将影响……`。
- 待确认句：`[Q] 需要补充……，否则不能确认……`。
- 法律句：`[L] 需完成[检索/法域审查/代理师判断]后再定性`。

“设计用于降低风险”可以在机制有支撑时使用；“已经降低”“确保”“显著提升”应有实验条件和原始数据。外部专利差异只能描述比较维度和待检索边界，不能从技术稿自身推出法律结论。

### 2.3 冲突优先级

1. 原始可定位文本或结构高于二手概括。
2. 实际计算输出高于正文口头描述。
3. 正式字段定义高于批注中的临时解释。
4. 可复演的输入—输出关系高于宣传性效果句。
5. 仍无法消解的冲突标 `[Q]`，冻结依赖它的模型、效果和支撑映射。

## 3. 数据/控制路线主链：`O → S → M → D → A → V → U`

本节主链仅适用于 `DATA_CONTROL_LOOP` 路线；`STRUCTURE_PHYSICS` 主题使用 0.1 节的结构链，不套用下表。

| 节点 | 要写清的内容 | 最小产物 | 典型追问 |
|---|---|---|---|
| `O` 观察 | 事件/数据来源、时间、身份、版本、缺失和延迟 | 可定位输入记录 | 何时采集？谁产生？能否复演？ |
| `S` 表示 | 状态、标签、编码、单位和取值域 | 状态/字段表 | 哪些字段会改变下游动作？标签是观测还是推断？ |
| `M` 模型/路由 | 规则、公式、模型、参数、版本和信息条件 | 模型契约/路由表 | 数据不足、冷启动、未知场景走哪条路径？ |
| `D` 决策 | 候选、评分/概率、阈值、成本、并列处理 | 决策表 | 低置信度、冲突、成本和风险怎样处理？ |
| `A` 动作 | 资源集合、排序、控制、权限、调度、缓存或降级 | 工程动作表 | 哪个模块执行？顺序、上限、接口是什么？ |
| `V` 验证 | 实际结果、命中/失配、超时、取消、重试和记录 | 状态机/指标定义 | 何时判定？任务 ID、版本和分母是什么？ |
| `U` 更新 | 更新对象、触发条件、幅度/公式、发布、回滚 | 更新协议 | 更新后如何验证？全局模型和个性化模型怎样隔离？ |

### 3.1 字段分层

至少分开以下变量：

- `event_t` / `op_t`：当前观察事件，不等于目的。
- `context_t`：环境、资源、场景或约束。
- `purpose_t` / `intent_t`：人工标签、规则推断或模型结果，必须写来源。
- `pred_event_(t+1)`：对未来事件的预测，必须用实际未来事件验证。
- `resource_t`：被请求、调度、控制或保护的资源集合。
- `feedback_t`：实际结果、错误、代价和统计窗口。

若一个词同时表示当前操作、用户目的和预测结果，先冻结建模，列出语义确认问题。样本材料在这一点上存在风险，见 `distillation/master-model.md` 第 2.3 节及 `distillation/sample-evidence.md` 第 10、11 节。

## 4. 八问式推理顺序

前一问没有闭合，不把后一问写成确定事实：

1. **现象：**系统/用户实际看到了什么异常？异常属于计算、通信、存储、调度、显示、控制、一致性层（数据路线），结构失效、装配干涉、超程超载、磨损疲劳（结构路线），还是偏差、污染、超时、中断（工艺路线）？
2. **时机：**系统本应何时作出什么选择？现有流程何时才拿到信息？
3. **状态：**哪些输入可观测？如何编码？状态改变哪一个后续动作？
4. **上下文：**哪些历史、环境、资源或约束真的改变决策？数据不足怎样降级？
5. **模型：**输入经何种公式、规则、统计或模型得到什么中间量？参数来源、单位、版本和边界是什么？
6. **动作：**输出如何决定资源、顺序、控制、权限、缓存或调度？
7. **错误：**预测错误、缺失、超时、冲突、资源不足或版本变化时如何停止、清理、回滚、重试或降级？
8. **验证：**实际结果如何判定？指标的分子、分母、基线、时间窗和反馈是什么？

## 5. 从输入包到交底书的十三步转换

输入可按以下概念结构整理，每个字段携带 `source`、`version`、`status`、`owner`、`date`：

```text
TopicPacket = {
  object, scenario, deployment,
  observable_events, current_workflow,
  known_constraints, existing_methods,
  proposed_mechanism, parameters,
  implementation_materials, experiments,
  external_references, open_questions
}
```

| 步骤 | 操作 | 产物 | 未通过时 |
|---|---|---|---|
| 1 | 锁定交付类型和证据等级 | 交付声明、附件清单 | 不能区分底稿/申请稿/实验稿时阻断对应标签 |
| 2 | 画系统边界 | 输入源、执行者、输出消费者、部署图 | 不写“系统自动”，转为边界追问 |
| 3 | 抽取可观察现象 | 场景—指标—代价—决策时机 | 只有宣传评价时转追问 |
| 4 | 切分现有方案缺口 | 缺口—原因—后果—比较维度 | 未检索不写“全部现有技术/无重合” |
| 5 | 定义问题和目的 | 问题—动作一一对应表 | 目的不能回指动作时降级为愿望 |
| 6 | 建立字段和术语表 | 事件、状态、目的、预测、资源、反馈 | 同词多义时冻结公式和效果 |
| 7 | 选择最小表示和模型路由（结构路线：连接关系与配合；工艺路线：步骤与工艺参数） | 状态域、冷启动/高信息分支 | 模型假设无数据支持时标 `[A]/[Q]` |
| 8 | 写计算契约（结构路线：尺寸链/工艺窗口契约；工艺路线：参数与判据契约） | 公式/伪代码、参数、归一化、版本 | 不可重算时不称“可实施” |
| 9 | 转成工程动作（结构路线：制造/装配动作；工艺路线：操作与处置动作） | 资源/控制/排序/时序/权限决策表 | 只有预测没有动作时退回步骤 8 |
| 10 | 设计验证与错误代价 | 成功、失配、超时、取消、回滚、重试状态机 | 缺任务 ID/终止条件时 P0/P1 |
| 11 | 编写实施例与替代例 | 输入—分支—中间量—输出—反馈轨迹 | 只有结果没有复演数据时降级为示意例 |
| 12 | 编写效果与边界 | 动作→系统量→指标→条件/基线/数据 | 缺实验只写机制预期或文档声称 |
| 13 | 做支撑、法律边界和质量审查 | 映射、追问台账、自审结果 | P0 未关闭则停止发布为已验证稿 |

## 6. 字段契约和结构依赖

任何核心步骤使用以下契约：

```text
字段契约 = 输入名称 + 类型/单位/版本 + 产生方式
        + 处理规则/公式 + 输出名称 + 下一步消费者
        + 缺失/冲突/异常处理 + 证据位置
```

标准字段依赖如下：

```text
交付范围/证据等级
  → 题名/主题 → 技术领域 → 背景和现有方案
  → 问题 → 目的 → 术语/状态/字段/约束
  → 总体方案 → 算法/接口/异常 → 验证和效果
  → 实施例/替代方案 → 创新点与支撑映射 → 待补信息/审查事项
```

核心特征候选应是所有有效实施都需要的输入—处理—输出关系。具体模型阶数、设备、协议、阈值、网络、缓存算法和示例数值，默认归入实施例或可选方案；若要上升为核心，必须有必要性、替代失败或跨实施支撑。

## 7. 语言与论证

### 7.1 段落微结构

推荐一段只推进一个可复核判断：

```text
系统采集 [事实输入]。
根据 [规则/模型/阈值]，确定 [中间决策]。
随后执行 [可观察动作]，并记录 [验证/反馈字段]。
```

技术标题宜采用“对象 + 核心机制 + 目标功能”；背景采用“场景 → 现有流程 → 具体缺陷 → 可观察后果 → 技术缺口”；总体方案采用“针对问题，提供一种……其核心在于……该方法包括……”。

### 7.2 动词预算

优先固定一组主动作，避免同义词漂移：

```text
采集 → 表示/编码 → 统计/计算 → 构建/选择 → 预测/筛选
→ 确定/排序 → 执行/调度 → 验证 → 更新/回滚
```

“结合、根据、同时、若”是关系词，不是隐藏步骤；“优化、实现、精准、确保、显著”必须拆成输入、动作、输出和条件。

### 7.3 技术效果四段式

```text
技术特征/动作
  → 直接改变的系统量
  → 可测指标
  → 测试条件、基线、样本和原始数据
```

例如，不能只写“智能预测显著降低延迟”，应写“根据预测结果排序候选资源并分批执行，改变资源请求顺序和缓存复用比例；在固定设备、网络、负载及基线下测量目标资源可用时间、无效请求量和取消任务占比”。缺少最后一段时，结论停留在“形成可测量机制/效果待验证”。

## 8. 实施例与替代方案

实施例不是效果口号，而是复演轨迹，至少给出：应用环境；输入事件/数据；状态和上下文；模型路由；中间结果；决策消歧；工程动作；正常和异常路径；缓存/接口/资源限制；反馈和版本（结构路线对应：工况环境、部件与装配顺序、动作过程中的受力/变形结果、失效轨迹与防护表现，见 `template.md` 第 9 节结构要素；工艺路线对应：原料与参数、中间态、偏差处置、检测记录）。替代方案应围绕功能等价点替换状态编码、模型/规则、数据源、设备、协议、缓存或调度策略（结构/工艺路线：材料、配合、工艺参数或处置方式），并说明保持的技术关系和变化的约束。

两类实施例可以采用“骨架固定、参数替换”结构，但这只证明结构可迁移的候选，不自动证明所有场景效果相同。每个数字都标出“核心/配置/示例/实验观察/待确认”身份。

## 9. 最小可实施包

在使用“可实施”“可复演”一类措辞前，至少检查：

- 术语、符号、变量、单位、版本和参数作用域表；
- 输入字段、来源、时间窗、缺省值和缺失处理；
- 公式、伪代码或确定性规则；
- 冷启动、低样本、并列、未知、超时、冲突、资源不足路径；
- 接口、缓存、并发、取消、重试、版本一致性规则；
- 至少一个脱敏或合成的最小复现数据包；
- 指标、基线、环境、样本、脚本、原始结果和统计口径；
- 附图、表格、外部资料和引用的唯一定位清单。

缺一项不代表不能写底稿，但应降低结论强度并进入待补台账。

## 10. 不能迁移的样本特例

不应默认复制：GIS 六操作状态、地图瓦片层级、马尔可夫一阶/二阶、具体权重、1.5—2 倍范围、5G/局域网、LRU、高频置顶、样本中的专利号和所有效果数字。跨领域时重新确认：长期依赖是否存在、状态粒度、资源单位、成本函数、错误代价、权限和回滚、验证口径。
